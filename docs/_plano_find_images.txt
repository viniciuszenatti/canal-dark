=== ref_provider ===
Wikimedia Commons é a melhor REF-ONLY sem chave — e na prática é melhor que isso: como cada arquivo carrega extmetadata.LicenseShortName/LicenseUrl por-imagem e foi confirmado HTTP 200 + URLs reais baixáveis no probe, dá pra usar o MESMO endpoint em dois modos: (a) lane=BURN quando a licença bate na allowlist (uso direto), (b) lane=REF-ONLY quando a licença é desconhecida/ambígua/NC/ND — aí baixa só pra pasta out/img_ref/ e marca needs_human_approval=true sem entrar no vídeo. Vantagem sobre One Piece Fandom: tem campo de licença legível por máquina, então o gate humano é só pro caso ambíguo, não pra tudo.

=== generate_provider ===
AI Horde (aihorde.net) é o gerador GENERATE viável grátis HOJE com chave anônima '0000000000' — probe AO VIVO retornou HTTP 202 (job aceito na fila). É assíncrono (POST /api/v2/generate/async → {id} → poll GET /api/v2/generate/status/{id} até done), lento na fila anônima e limitado a imagens pequenas (<=512x512, <=20 steps) sem kudos, mas é genuinamente sem custo e sem cartão. Pollinations.ai NÃO deve ser o primary: apesar de o probe ter dado HTTP 200 com JPEG válido AGORA, o brief avisa que virou 402 recentemente E a própria resposta trouxe o header 'access-control-allow-headers: ...X-PAYMENT' (sinal de monetização em curso). Conclusão honesta: NÃO existe gerador grátis robusto e síncrono sem chave em 2026 — AI Horde é o único sem-chave confiável mas é lento; Pollinations entra só como tentativa best-effort com checagem de status em runtime (se !=200 ou content-type!=image, descarta). Geradores REALMENTE bons (Cloudflare Workers AI / FLUX-schnell) precisam de chave (free-with-key), então ficam fora da regra 'sem chave paga' até o usuário optar por criar conta Cloudflare grátis.

=== find_images_design ===
ASSINATURA: find_images(query: str, niche: str, lane: str, count: int = 1, out_dir: Path = OUT/'img_cache') -> list[Path].

LANES: 'burn' (default p/ tudo monetizado), 'anime' (gated por ALLOW_ANIME=1), 'ref' (só baixa p/ out/img_ref/, marca needs_human_approval), 'generate'. O chamador passa lane derivada do nicho/subject_mode; default sempre 'burn'.

ORDEM DE PROVIDERS POR LANE (lida de env, com default sensato):
  - burn  : [wikimedia, openverse, internetarchive]  (todos com licença por-arquivo verificável)
  - generate: [aihorde, pollinations]  (aihorde primeiro pq é o sem-chave confiável; pollinations best-effort com checagem 200+content-type)
  - anime : [] por padrão (vazio = desligado); só [fandom, civitai] se ALLOW_ANIME=1, e mesmo assim marca needs_human_approval
  - ref   : [wikimedia, internetarchive] em modo só-referência (não entra no vídeo)
Por-nicho: mapa NICHE_LANE_HINT (ex history->burn preferindo wikimedia+internetarchive; science->burn wikimedia+openverse; anime-nicho->generate primeiro, depois anime gated). Nicho só REORDENA a lista da lane, nunca fura o gate de copyright.

LÓGICA: 1) normaliza query (strip, 1ª cena antes de vírgula, reusa _tokenize do short_factory pra dedupe). 2) calcula cache_key = sha1(provider+query+lane+index)[:16]; se out_dir/{cache_key}.jpg existe E out_dir/{cache_key}.json (sidecar de licença) existe -> retorna do cache (dedupe inter-execução). 3) percorre providers da lane em ordem; cada provider é uma função provider_fn(query, count) -> list[ImageResult] onde ImageResult={url|bytes, license, attribution, source_provider, source_url, needs_human_approval}. 4) FILTRO BURN: descarta qualquer result cuja license não esteja na BURN_ALLOWLIST (PD/CC0/CC-BY/CC-BY-SA); descarta NC e ND sempre. 5) DEDUPE: mantém set de hashes (sha1 dos bytes baixados) + set de source_url já vistos nesta run pra não repetir a mesma imagem em 2 linhas. 6) baixa via requests (reusa timeout/stream do _fetch_pexels), valida content-type image/* e tamanho > 2KB (mesma guarda do _fetch_pollinations que checa <1000 bytes). 7) grava {cache_key}.jpg + sidecar {cache_key}.json com {provider, source_url, license, attribution, query, lane, ts}. 8) acumula crédito num CREDITS.jsonl append em out/.

FALLBACK PRO PEXELS: find_images NÃO baixa vídeo; se a lane esgotar todos os providers sem imagem válida (ou lane='ref' que nunca entra no vídeo), retorna [] e o chamador (fetch_broll) cai no _fetch_pexels existente -> e este já tem o piso de cor sólida (create_solid_color_clip). Cadeia: imagem-livre -> (vazio) -> Pexels vídeo -> (None) -> cor sólida. Zero regressão: se IMG_PROVIDERS estiver vazio/desligado, find_images retorna [] na hora e o comportamento atual (só Pexels) é idêntico.

REGISTRO DE LICENÇA: cada imagem usada gera 1 linha em out/CREDITS.jsonl + sidecar .json no cache; assemble_short no fim concatena os créditos num bloco pra description do vídeo.

=== attribution_rule ===
Toda imagem que entra no vídeo grava 2 artefatos: (1) um sidecar JSON ao lado do arquivo no cache out/img_cache/{hash}.json com {provider, source_url, license, license_url, attribution, artist, query, lane, used_in_run, timestamp}; (2) 1 linha append-only em out/CREDITS.jsonl por uso. No fim do pipeline, assemble_short/build_publication_metadata concatena os créditos num bloco de texto 'Image credits:' anexado à description do metadata.json (que vai pro YouTube/Postiz). Regra por licença: CC0/Public Domain -> crédito OPCIONAL mas registrado mesmo assim; CC-BY/CC-BY-SA -> crédito OBRIGATÓRIO no formato 'Artist - Título (LicenseShortName) via Provider, source_url' (Wikimedia entrega Artist+LicenseShortName; Openverse entrega a string attribution pronta — usar literal). Geradas por IA (AI Horde/Pollinations) -> registrar provider+prompt+seed, sem crédito de copyright de foto. REF-ONLY -> nunca chega aqui (não entra no vídeo). Se uma imagem CC-BY for usada e por algum motivo o crédito não puder ser montado (campo Artist vazio), a imagem é DESCARTADA, não usada sem crédito.
